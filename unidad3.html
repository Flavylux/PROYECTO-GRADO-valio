1. Sistemas de Numeración y Código Binario

La computadora está compuesta por miles de millones de transistores que reconocen dos estados físicos: presencia o ausencia de tensión eléctrica. Por ello, la lógica binaria (0 y 1) es la base de la representación de datos. 

                      SISTEMAS NUMERICOS
                               |
      +------------------------+------------------------+
      |                        |                        |
Sistema Decimal          Sistema Binario        Sistema Hexadecimal
 (Base 10: 0-9)           (Base 2: 0, 1)        (Base 16: 0-9, A-F)
Lenguaje Humano          Lenguaje Maquina          Direccionamiento

Los sistemas posicionales

  • Sistema Decimal (Base 10): usa diez simbolos (0-9), cada posicion representa potencias de 10.
  • Sistema Binario (Base 2): usa 0 y 1; cada posicion representa potencias de 2.
  • Sistema Hexadecimal (Base 16): usa 0-9 y A-F para resumir secuencias binarias largas.

Conversion entre bases numericas

  • Binario a Decimal: multiplicar cada bit por 2 elevado a su posicion y sumar resultados. 
    1011₂ = (1 x 2^3) + (0 x 2^2) + (1 x 2^1) + (1 x 2^0) = 11₁₀
  • Decimal a Binario: divisiones sucesivas entre 2 y lectura inversa de residuos. 
    25/2=12 r1
12/2=6  r0
6/2=3   r0
3/2=1   r1
Resultado: 11001₂

Representacion de datos en memoria

  • Bit: unidad minima de informacion (0 o 1).
  • Byte: conjunto de 8 bits.
  • Multipos digitales: KB = 1024 bytes, MB = 1024 KB, GB = 1024 MB, TB = 1024 GB.

2. Algoritmos y Diagramas de Flujo

Un algoritmo es una secuencia ordenada, finita, precisa y no ambigua de pasos logicos que transforma entradas en salidas.

Propiedades fundamentales de un algoritmo

  1. Precision: cada paso debe ser claro y sin ambiguedad.
  2. Finitud: el algoritmo termina tras un numero finito de pasos.
  3. Definicion: misma entrada implica mismo resultado.
  4. Estructura estandar: entrada, proceso y salida.

Diagramas de flujo

       [ INICIO ]
           |
           v
   / Leer valor de A /
           |
           v
   [ Resultado = A * 2 ]
           |
           v
      / ?A > 10? /
      /          \
  (Si) /          \ (No)
      v            v
 [ Imprimir X ] [ Imprimir Y ]
      \            /
       v          v
        ( FIN )

Simbologia ANSI/ISO

  • Ovalo/Terminal: inicio y fin.
  • Paralelogramo: entrada/salida de datos.
  • Rectangulo: proceso o calculo.
  • Rombo: decision logica (verdadero/falso).
  • Flechas: sentido de ejecucion.
  • Conector circular: enlaza tramos del diagrama.

3. Metodologia de Analisis, Diseno, Desarrollo y Evaluacion

El Ciclo de Vida del Desarrollo de Software (SDLC) organiza el trabajo para construir soluciones de calidad, escalables y mantenibles. 

+---------------------------------------------------------------+
|                       1. ANALISIS                             |
|          Comprender el problema y determinar inputs/outputs   |
+---------------------------------------------------------------+
                               |
                               v
+---------------------------------------------------------------+
|                        2. DISENO                              |
|           Estructurar la solucion (Diagramas / Algoritmos)    |
+---------------------------------------------------------------+
                               |
                               v
+---------------------------------------------------------------+
|                      3. DESARROLLO                            |
|             Traduccion a codigo en un lenguaje                |
+---------------------------------------------------------------+
                               |
                               v
+---------------------------------------------------------------+
|                      4. EVALUACION                            |
|           Pruebas de software, depuracion y validacion        |
+---------------------------------------------------------------+

Fases del SDLC

  • Fase 1 - Analisis: identificar entradas, procesos, salidas y restricciones del problema.
  • Fase 2 - Diseno: definir la arquitectura logica con diagramas, pseudocodigo y estructura de datos.
  • Fase 3 - Desarrollo: implementar el diseno en un lenguaje formal (Python, C++, JavaScript, etc.).
  • Fase 4 - Evaluacion: pruebas, verificacion, validacion y depuracion de bugs.

4. Diferenciacion de Conceptos Esenciales en Informatica

Software vs. Hardware

  • Hardware: parte fisica y tangible del sistema informatico.
  • Software: parte logica e intangible que indica al hardware que hacer.

Lenguajes compilados vs. interpretados

  • Compilados (C, C++, Rust): generan ejecutable binario; mayor rendimiento, menor portabilidad directa.
  • Interpretados (Python, JavaScript, Ruby): ejecucion linea por linea; desarrollo agil y facil depuracion.

Logica vs. sintaxis

  • Logica de programacion: estructura universal para resolver problemas paso a paso.
  • Sintaxis: reglas gramaticales especificas de cada lenguaje.

5. Introduccion a la Logica Programable con PSeInt

PSeInt es una herramienta educativa orientada a estudiantes hispanohablantes para desarrollar logica algoritmica antes de abordar sintaxis complejas.

Pseudocodigo como puente al codigo real

El pseudocodigo usa lenguaje natural y estructura de programacion para describir algoritmos de forma clara, facilitando la transicion a Python o C.

Estructura general en PSeInt

Algoritmo CalcularPromedio
    // Declaracion de variables
    Definir nota1, nota2, promedio Como Real

    // Entrada de datos
    Escribir "Ingrese la primera nota:"
    Leer nota1
    Escribir "Ingrese la segunda nota:"
    Leer nota2

    // Proceso
    promedio <- (nota1 + nota2) / 2

    // Salida
    Escribir "El promedio final es: ", promedio
FinAlgoritmo

Elementos basicos de PSeInt

  1. Comentarios (//): notas para humanos, ignoradas por el interprete.
  2. Definicion de variables: reserva de memoria con tipo de dato.
  3. Escribir y Leer: salida de mensajes y captura de entrada del usuario.
  4. Asignacion (<- o =): guarda en una variable el resultado de una expresion.
  5. Generacion de diagramas: conversion entre pseudocodigo y diagrama de flujo.
